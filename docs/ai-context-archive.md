# Архив AI-контекста: blog (Flask)

Факты завершённых раундов. Правила заполнения архива:
- Записи с заголовками вида `ARC-NNNN`.
- Append-only - записи не удаляются, не правятся задним числом; устаревшие помечаются `[УСТАРЕЛО → ARC-XXXX]`, текст 
  сохраняется. 
- Записи идут встык; граница записи - заголовок следующей. 

Договорённости по проекту находятся в ядре (`ai-context.md`).  
Запросы от AI по получение данных из архива: 
- «Покажи ARC-0007» - пользователь отправляет в чат запись включая заголовок. 
- «Покажи ARC-0001–0009» - пользователь отправляет в чат несколько записей (диапазон) одним сообщением.
- «Покажи оглавление архива» - пользователь отправляет в чат только таблицу оглавления.

## ARC-0041. Ролевая модель SuperAdministrator. 2026-11-20.

Формулировка: роль SuperAdministrator — иерархия user < admin < superadmin (ROLE_SCOPES + role_includes в
constants.py — единственная точка истины). SUPERADMIN уникален, через API/WEB не выдаётся и не снимается —
канал только CLI (make-superadmin с отказом при существующем; delete-user для смены хозяина). Смена ролей
USER↔ADMIN — только супер-админом, себе запрещена (403); сервисные гварды до обращения к БД — defense-in-depth
поверх @role_required.

Что сделано:
- constants.py: Roles.SUPERADMIN, ROLE_SCOPES, role_includes, ROLE_TITLES (человекочитаемые для флеша).
- user_service.change_role (гварды: не-супер → ForbiddenError, себе → ForbiddenError, роль вне поверхности
  USER/ADMIN → BadRequestError); admin_service — тонкий гвард-делегат без изменений в поведении.
- API: PATCH /api/users/<id>; карта 401 → 403 → 400 (нет ключа role / роль вне поверхности) → 404 → 200;
  повтор смены идемпотентен; супер-админ проходит существующие админ-эндпоинты по иерархии.
- WEB: POST /user/<username>/role → 302 + флеш; контролы (dropdown + «Изменить» + confirm-модалка) — только
  супер-админу и только на чужом профиле; не-супер в прямой POST → 404 (действие скрыто), гость → 302 на логин.
- Бейджи ролей в профиле и админ-списке (ROLE_BADGE_CLASSES) — сверх минимального скоупа, приняты.
- CLI: make-superadmin, delete-user; обе команды зарегистрированы в фабрике.

Решения:
- Иерархия — одна точка истины; потребители не держат своих таблиц.
- WEB прячет действие от не-суперов (404, не 403) — поверхность не раскрывает существование эндпоинта.
- SUPERADMIN не поднимается интерфейсами: роль уникальна, хозяин меняется только двухшагово через CLI.

Инциденты раунда:
- Кнопка и заголовок модалки врали на смене роли («Удалить», «Подтверждение удаления») → confirm_action.js
  перезаписывает заголовок/текст/подпись кнопки по data-action; статичный текст base.html — заглушка.

  флеш — осознанное исключение (см. бэклог п. 23).
- confirm_delete.js → confirm_action.js: имя перестало соответствовать содержимому.

Уроки:

  напрямую, минуя фабрику. → Гвард в бэклоге п. 22.

  SoftAssert падает с «'NoneType' object is not callable».

# AI-контекст разработки проекта: blog (Flask)

Два контекста (→ ARC-0060): этот файл — договорённости о разработке; ai-context-testing.md — договорённости
о тестировании (запрос «Дай контекст для реализации тестов», присылается вместе с картой). Ритм раунда: сначала
функциональность — по этому контексту, затем покрытие тестами — по тестовому; для генерации кода функциональности
тестовый контекст не нужен. Бэклог и счёт живут только здесь.
Ядро — только действующие решения, каноны и карта. История — в архиве (ai-context-archive.md, записи ARC-NNNN,
оглавление в шапке; запросы: «Покажи ARC-0007», «Покажи ARC-0001–0009», «Покажи оглавление архива»).
Карта структуры проекта — docs/project_structure.md: единственная точка истины «где и что», аннотация на модуль,
ссылки → ARC-NNNN; прикладывается к сессии вместе с активным контекстом.
Ссылки из ядра — в формате → ARC-NNNN. Критерий строки ядра: «если забыть — сломает следующую работу?».
Строки с пометкой [общая] продублированы в тестовом контексте — править синхронно в обоих файлах.
Правило закрытия раунда: ядро меняется максимум на ±3 строки (секция раунда + бэклог + счёт), остальное —
одной записью в архив; в конце раунда ядро выдаётся целиком (тестовый контекст — только если менялся канон
тестов). Исключение — реформы контекста (ARC-0028, ARC-0055, ARC-0060): сознательная пересборка с выдачей целиком.

## 1. Стек и окружение

- Shell: `flask --app "blog:create_app()" shell`.
- Верификация раунда: `pytest -v`, `ruff check blog tests`, `coverage run -m pytest && coverage report -m`. [общая]

## 2. Архитектура приложения
- Слои: роуты (blueprints: api, web, admin) → сервисы → модели. Роуты тонкие: валидация/flash/redirect,
  логика — в сервисах.
- blog/services/base_errors.py: ServiceError (500) → NotFoundError (404), ForbiddenError (403),
  BadRequestError (400), ConflictError (409). Ошибки бизнес-логики — только этими классами.
- WEB: @web_errors; API: @api_errors → JSON {'error': ...} со статусом из исключения.
  Порядок декораторов: @api_errors сверху.
- Исключение: /api/token отвечает 401 напрямую dict (нет доменных исключений).
- Константы — blog/constants.py: POSTS_PER_PAGE = 5, COMMENTS_PER_PAGE = 10, USERS_PER_PAGE = 20,
  MAX_PER_PAGE = 50, Roles (USER, ADMIN, SUPERADMIN), ROLE_SCOPES и role_includes (иерархия ролей —
  единственная точка истины; → ARC-0041), ROLE_DISPLAY_NAMES/ROLE_BADGE_CLASSES/ROLE_TARGET_OPTIONS
  (ролевые карты: человекочитаемые названия — язык UI; сырые значения — в value dropdown, API и БД;
  → ARC-0043), PROFILE_TAB_POSTS/PROFILE_TAB_COMMENTS/PROFILE_TABS.
  Строки ролей в коде не используются — только константы.
- pyproject: requires-python >=3.15; ruff — line-length 120, py315, E/F/I/UP/B/Q/D, pydocstyle google,
  ignore-decorators ["wraps"]; coverage — branch=true, source=["blog"].
- Чистое состояние (тесты зелёные, Ruff ноль, покрытие 100%) — умолчание закрытия раунда, не фиксируется;
  записывается только отклонение.

## 3. Аутентификация и роли
- JWT (flask-jwt-extended): /api/token, /api/register; WEB — сессии (Flask-Login).
- Роль — по БД через get_current_user(), не через JWT claims (смена роли действует сразу).
  Декоратор role_required(*roles); User.is_admin существует, но проверка идёт через role in roles.
- loaders.py: @login_manager.user_loader + @jwt.user_lookup_loader; регистрация при импорте — фабрика делает
  `import blog.loaders  # noqa: F401` ради декораторов. Файл живой, НЕ удалять (→ ARC-0009).
- CLI — все в blog/cli.py: `flask make-admin`, `flask create-admin`, `flask clean-uploads` (чистка сирот
  uploads, → ARC-0033), `flask make-superadmin` (отказ, если супер-админ уже существует; смена хозяина —
  delete-user, затем make-superadmin), `flask delete-user` (→ ARC-0041).
- Новые CLI-команды регистрируются add_command в фабрике приложения: invoke_cli в тестах зовёт click
  напрямую, живой Flask без регистрации команду не видит; регистрация накрыта юнит-гвардом
  test_cli_registration.py (→ ARC-0041, ARC-0043).
- create-admin: дубль имени — «уже существует», пароль не перезаписывается.
- auth_service: authenticate / register_user; ошибки — исключениями (пустое имя или пароль короче 4 символов →
  BadRequestError; дубль → ConflictError). POST /api/register → 201 {"user": {...}}; username strip — пустая → 400.
- WEB-аутентификация: гость — 302 на логин; под сессией GET /login|/register — 302 на главную; next: внутренние
  пути работают, внешний/`//evil.site`/без ведущего слеша → на главную (open redirect закрыт).

## 4. Пользователи: админ-API и WEB-админка
- API: GET /api/users, DELETE /api/users/<id>; admin_service.list_users / delete_user(user_id, actor).
  Не-админ → 403 (проверка роли ДО поиска); самоудаление → 403; нет пользователя → 404. Сервисный гвард —
  defense-in-depth (юнит-тест), декоратор — ранний барьер.
- WEB-админка: гость → 302; не-админ → 404 (не подсказывать скрытые роуты); админ → 200; самоудаление → 403;
  нет id → 404. Расхождение WEB/API — осознанное (API честно 403, WEB прячет 404).
- Роли (→ ARC-0041): SUPERADMIN уникален, выдаётся/снимается только через CLI; смена USER↔ADMIN — только
  супер-админом, себе нельзя (403). API PATCH /api/users/<id> (карта 401→403→400→404→200, повтор
  идемпотентен; супер-админ проходит существующие админ-эндпоинты по иерархии); WEB POST
  /user/<username>/role (302 + флеш «Роль изменена на Administrator.», контролы — dropdown сырых ролей +
  «Изменить» + confirm-модалка — видит только супер-админ на чужом профиле; не-супер прямой POST → 404,
  гость → 302). Бейджи ролей в профиле и админке — человекочитаемые названия (→ ARC-0043).
- Фирменные ошибки: errorhandler(404)/(500) в фабрике + errors/404.html, errors/500.html;
  один 404-хендлер ловит и роутинг, и NotFoundError админки.
- Хедер: пункт «Административная панель» только при is_authenticated and is_admin; меню для остальных пустое
  сознательно (вернёмся с профилем).
- Каскадное удаление Post ↔ User: Post.author_id — FK ondelete='CASCADE'; naming convention в extensions.py;
  conftest — PRAGMA foreign_keys=ON; User.posts — cascade='all, delete-orphan' + passive_deletes=True.

## 5. Посты и комментарии: контракты и пагинация
- post_service.list_posts(page=1, per_page=POSTS_PER_PAGE) -> Pagination: db.paginate, error_out=False
  (за пределами total → пустой список, не 404); сортировка Post.created.desc(), Post.id.desc().
- WEB-лента: ?page — санитизация через общие хелперы pagination.py (→ ARC-0032);
  index.html — Bootstrap-навигация (has_prev/has_next/pages).
- API GET /api/posts — конверт: posts, page, pages, total, per_page (в конверте применённый
  per_page = pagination.per_page). Санитизация: page — мусор/<1 → 1; per_page — мусор/<1 → POSTS_PER_PAGE, > 50 → 50.
- Модель Post: body — сырой Markdown; comment_count — column_property со scalar subquery + correlate_except(Comment)
  (→ ARC-0037; N+1 счётчика убран).
- Markdown: два уровня в пакете markdown/ (→ ARC-0050, распил → ARC-0058). render_markdown — посты
  (расширенный): "" → "", иначе mistune-рендер → nh3.clean; порядок обязателен (рендер, потом санитизация).
  render_markdown_basic — комментарии (базовый, Jinja-фильтр markdown_basic): whitelist тегов nh3 (_BASIC_TAGS),
  заголовки/таблицы деградируют до текста, картинки видны синтаксисом, переносы без nl2br. _BootstrapRenderer:
  block_quote → class="blockquote". Рельс кастомных плагинов: реестр _PLUGINS + _build_renderer() — раунды В и С.
  В шаблонах — только фильтры markdown / markdown_basic и всегда |safe (вызов функции из шаблона —
  UndefinedError); update.html и comment_update.html — сырой Markdown в textarea.
  teaser-фильтр удалён (лента обрезает CSS).
- Видео :::video[url] (→ ARC-0052, ARC-0056): block-плагин расширенного уровня (в комментарии базового уровня не
  наследуется), срабатывает только на строке с начала строки — пустая строка перед конструкцией обязательна.
  YouTube работает (watch/shorts/live/youtu.be, ID ровно 11 символов [0-9A-Za-z_-]); VK-адрес из кнопки
  «Встроить» (video_ext.php) проносится вербатимом — пересборка ломает hash. Деградация в ссылку/текст по
  канону «что написал, то и увидишь». Вывод: escape(quote=True) + nh3-карта с div/iframe.
  RuTube (→ ARC-0056): play/embed/<32 hex> — вербатимом, включая ?p= приватных роликов; страницы
  /video/<32 hex>/ и /video/private/<32 hex>/ пересобираются в embed (hash у RuTube нет — безопасно).
  VK и RuTube работают на «взрослых» origin: file:// и IP-localhost VK отвергает сам (диагностика → ARC-0056) —
  на локальной разработке VK-встройки не работают, это не баг; на домене (blogtest.local, прод) работают.
- Блоки изображений (→ ARC-0057): :::img[alt](url, классы) — whitelist w-25/w-50/w-75/w-100, float-start/float-end,
  rounded; неизвестный класс — деградация в обычную markdown-картинку. :::gallery/:::carousel — контейнеры строк
  :::img, деградация контейнера — экранированный текст. Карусель: data-bs-ride, кнопки не рендерятся сознательно
  (nh3 вырезает button/data-bs-* → п. 30); классы слайдов — тот же whitelist, что у :::img, неизвестный токен —
  деградация всего блока (→ ARC-0059). Утилиты Bootstrap (с !important) в рендер-разметке кастомных блоков
  не смешивать с кастомной CSS-раскладкой — раскладка целиком в blog.css.
- Права на контент (посты и комментарии) — единая модель permissions.py: ensure_allowed (author_id, actor,
  action, subject); Action.UPDATE/DELETE; автор — всё со своим; админ — только удаление чужого, одинаково
  в WEB и API; чужое редактирование — 403 (→ ARC-0038). Гварды в сервисах сняты (check_author удалён);
  порядок 404 → 403 — get_* до ensure_allowed. Гость: WEB 302 / API 401.
- Профиль /user/<username> — публичный; вкладки лент как ссылки: ?tab=posts|comments (мусор → posts), одна
  пагинация page внутри активной вкладки; get_profile(username, tab, page) отдаёт одну ленту через карту
  _FEEDS; новые разделы — строкой в карту (→ ARC-0039).
- Комментарии: Comment(id, post_id FK CASCADE, author_id FK CASCADE, body, created_at). Новые сверху —
  сортировка created.desc() с обязательным тайбрейком id.desc() (сортировка по created без id
  недетерминированна при массовом создании; → ARC-0040). Рендер — Markdown базового уровня (→ ARC-0050).
  Список комментариев поста: comment_service.list_for_post(post_id, page, per_page) → Pagination;
  COMMENTS_PER_PAGE = 10; API — конверт как у постов; ?page на странице поста листает комментарии
  (одна лента — один query-параметр; → ARC-0040).
- WEB-роуты постов: пустой/whitespace title — флеш с ошибкой; валидация body отсутствует осознанно.

## 6. Статика и JS
- Канон кастомного JS (→ ARC-0030): один файл = один самодостаточный виджет, подключается только там, где нужен;
  ось организации — точка загрузки, НЕ домен. Граница пересмотра: общий код у файлов или 10+ файлов →
  modules/сборка. Шапка-комментарий с якорями и страницами подключения обязательна; 'use strict' первой строкой;
  именованные константы наверху файла; vanilla JS + публичный API Bootstrap; скрипты в конце <body> без defer —
  DOMContentLoaded не нужен; инлайн-скрипты в шаблонах запрещены; JS вне тестового покрытия осознанно
  (верификация — ручная проверка); ESLint не вводим. Перечень файлов и точек подключения — в карте.
- EasyMDE 2.21.0 (CDN, без SRI осознанно) — на четырёх формах: посты (create/update) и комментарии
  (view, comment_update); на view CDN внутри блока «авторизован» (гостю редактор не нужен). Загрузка
  изображений — только формы постов: POST /uploads (XHR ради onprogress), ошибки в JSON-плашке-индикаторе;
  клиентский лимит 50 МБ — MAX_IMAGE_SIZE в md_editor_init.js (→ ARC-0044, ARC-0047). Тулбар комментария —
  зеркало базового уровня: без кнопок заголовка и картинки (→ ARC-0050); preview рендерит клиентским
  парсером и может показать чуть больше, чем сервер (известное ограничение). required на textarea
  редактора не ставится (невидимое required роняет сабмит).
- CDN Bootstrap 5.3.8 — с integrity (SRI). Кастомные CSS/JS — осознанное исключение из «чистого Bootstrap».
- CSS-тизер ленты: .post-clip 24rem (подобрано глазами, → ARC-0045), анимация раскрытия с жёстким каноном
  замера «fits» — порог следует за CSS, констант в JS нет; замер после «Свернуть» отложен до transitionend
  (→ ARC-0048). Картинки в постах не ломают вёрстку: .post-clip img — max-width 100% (→ ARC-0033).
- Тост-стек флешей: fixed снизу по центру, z-index 1045 (ниже модалки 1055), prefers-reduced-motion.
- Шпаргалка Markdown у редактора (→ ARC-0042, ARC-0047): collapse-кнопка после textarea #body на формах постов;

  рендером iframe, → ARC-0052); примеры — источники, доступные из РФ (RUPixel, VK; → ARC-0057).
- Макросы шаблонов (macros.html, импорт один — в base.html, дочерние наследуют): avatar(user, size) и
  pagination_nav(pagination, endpoint) — единая постраничная навигация всех лент (раньше три копии, → ARC-0046):

## 8. Процесс работы с AI
- Два контекста (→ ARC-0060): этот файл — разработка; ai-context-testing.md — тестирование. Функциональная
  работа раунда идёт по этому файлу; тестовая фаза — по запросу «Дай контекст для реализации тестов»
  (присылается тестовый контекст + карта). Карта одна для обоих миров.
- Сессия: пользователь присылает активный контекст и карту структуры (оглавление архива — при необходимости);
  AI выдаёт обновлённые версии к концу раунда: ядро разработки — всегда, тестовый контекст — только если менялся
  канон тестов. Файлы не хранятся в контейнере — при потере просить у пользователя, не восстанавливать по памяти.
- Карта структуры (docs/project_structure.md) — точка истины «где и что»: структура, модули, точки подключения.
  Ядро — «почему так, каноны и что нельзя». Перечни файлов в ядре не держим — карта; если раунд меняет структуру,
  карта обновляется вместе с ядром в конце раунда (→ ARC-0055).
- Режим: план — названия шагов; один шаг за раз: правка → присылка модуля → проверка и актуализация → следующий
  шаг. [общая]
- Один вопрос за раз: параллельное обсуждение нескольких тем при активной задаче привело к потере
  договорённостей — обсуждение закрывается фиксацией (архив/бэклог) до перехода к следующей теме (→ ARC-0054).
  [общая]
- Канон передачи — полные файлы: изменённый модуль выдаётся в чате целиком, пользователь заменяет файл на диске
  целиком; куски для патча не ищутся. Ядро — целиком в конце каждого раунда. Перед выдачей целого файла AI
  опирается на актуальную версию с диска: если есть ручные правки, не дошедшие до AI, файл запрашивается заново —
  ручные правки не теряются. Подтверждение сохранения — вложением файлов. Приложенный файл затирает одноимённый
  на диске. Сохранение подтверждается явно (→ ARC-0012, ARC-0015). [общая]
- Ruff — зона ответственности пользователя: AI не отслеживает замечания форматирования и линта (импорты, кавычки,
  стиль docstring и прочее, что проверяет Ruff) ни в патчах, ни в промежуточных прогонах; исключение — замечания
  с функциональными последствиями. В конце раунда пользователь приводит код в порядок и прогоняет Ruff;
  AI комментирует результат только если что-то сломалось. [общая]
- Длина строки .py/.md — 120 символов; html/js/css — по best-practices. [общая]
- Уроки: имена API сверять с документацией до кода. Диагностика: временные принты — рабочая практика, снимаются
  после фикса. Регэкспы и экранирования сверять посимвольно после сохранения (→ ARC-0049).
- Восстановимые данные (coverage, git, код) в контексте не хранятся.
